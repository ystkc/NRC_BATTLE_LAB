# 屏幕 OCR

Windows 桌面上的周期 OCR 与触发器执行程序，使用浏览器配置。支持 Python 3.10 及以上版本。

## 启动

在 NRC Battle Lab 根目录运行以下命令。

```powershell
python -m pip install -r requirements.txt
python -m screen_recorder
```

在已解锁的 Windows 桌面会话中启动服务，再打开 [本地工作台](http://127.0.0.1:8768)。可用 `--port 8770` 修改端口。文字识别使用带中文模型的 RapidOCR 和 ONNX Runtime。

## 使用

1. 在「截图来源」选择显示器或应用窗口，再点击「获取截图」。使用显示器且浏览器与目标窗口在同一屏时，可选「3 秒后」截图，再切到目标窗口。
2. 点击「框选」后拖出矩形，填写唯一的备注名。拖动圆形手柄可旋转矩形，也可在右栏输入顺时针倾角。用「校正预览」检查文字方向。关闭「每轮识别」可将区域留给条件和额外 OCR 使用。选中已有框后，可用「复制区域」复用它的几何和识别设置。
3. 设置频率（Hz）并添加触发器。每个触发器的条件须全部满足，空条件会每轮执行。触发器和操作都按界面顺序执行，可用上移、下移按钮调整。

   截图编辑区绘制当前选中的区域、「每轮识别」区域，以及已勾选「显示」的触发器所引用的区域，包括触发条件、额外 OCR 和点击候选条件。触发器默认勾选「显示」，该设置随配置保存。
4. 用「试跑一轮」检查 YAML、置信度和拟点击坐标。点击「开始运行」开始连续识别和实际点击。可以设定启动延迟，留出返回目标窗口的时间。

### 窗口截图

窗口模式使用 Windows Graphics Capture 读取所选窗口的客户区，要求 Windows 10 1903 或更新版本。窗口可被其他应用遮挡，运行时请保持窗口处于恢复状态。窗口移动时区域坐标仍以客户区为基准。窗口大小变化后，请刷新列表、重新选择窗口并检查截图中的区域和坐标。

随机点击使用桌面鼠标。如果选中的位置被遮挡或移到屏幕外，本次点击会跳过，原因会写入 YAML。

### OCR 模型

「检测模型」负责定位文字，「识别模型」负责将文字转成文本。送入模型前会用选区边缘的颜色填充留白，减少贴边文字漏检。两者可分别选择 PP-OCRv6 Tiny、Small、Medium。默认使用包内的 Small，首次选择其他预设时 RapidOCR 会下载缺失的模型文件。

选择「本地 ONNX」可填入本机兼容 RapidOCR 的模型路径。识别模型缺少内置字典时，填入与模型匹配的 UTF-8 字符字典路径。相对路径以启动服务的目录为基准。

模型在任务启动倒计时前加载。只要分级清单有配置，「开始运行」和「试跑一轮」都会加载清单中的全部识别模型，并用标准尺寸图片各预热一次。服务进程分别缓存最近使用的四个检测和四个识别阶段，切换其中一项时可复用另一项的 ONNX 会话。本地文件的大小或修改时间变化后，下次运行会重新加载该模型或字典。

在全局设置展开「置信度不足时提高参数量」，按尝试顺序添加识别模型和 0 到 1 的通过阈值。然后在需要使用这组模型的区域勾选「分级识别」。每次识别从第一项开始，有文字且每行置信度都达到本项阈值时采用该次结果。空结果或任一行低于阈值会尝试下一项，全部未通过时输出 `null`。启用分级识别的区域使用各阶段阈值，其他区域使用全局默认识别模型和区域置信度下限。检测模型和允许字符对各次尝试均生效。

### 区域识别设置

每个区域可单独设置 `detect`、`confidence` 和 `frame_diff_threshold`。默认开启文字框检测，两个阈值默认都是 0。关闭检测会将整个校正选区作为一行识别。置信度下限为 0 到 1，保留分数达到下限的文字行。

「允许字符」对应 `allowed_chars`，留空使用模型的全部字符。纯数字填 `0123456789`，血量如 `480/480` 填 `0123456789/`。限制在识别模型解码时生效。手写 YAML 时请给字符列表加引号。

同一张截图中关闭检测的区域先检查帧差，再将需要识别且模型输入宽度、允许字符集合相同的裁剪图交给 RapidOCR 批量识别。

帧差是当前裁剪图与上一次实际执行 OCR 的裁剪图之间的平均绝对像素差，按 0 到 1 归一化。小于或等于阈值时沿用缓存的文字及置信度。阈值为 0 时只对相同画面使用缓存。再次得到有效文字时，区域的跳过帧数归零。

每轮结束时只保留本轮读取过的区域缓存。每轮识别、触发器条件和操作中读取的 OCR 框都计入。本轮未读取的区域下次读取时重新执行 OCR。

### 条件与操作

| 条件或操作 | 判定和执行方式 |
|---|---|
| OCR 置信度 | 区域中任意一行的置信度严格大于阈值，阈值为 0 到 1。 |
| OCR 文字 | 支持包含和完全相同，区分大小写，将连续空白合并成一个空格后比较。 |
| 前置触发器已触发 | 所选触发器排在当前触发器之前，且本轮已进入操作步骤。每轮重新判定。 |
| 像素颜色 | R、G、B 各通道与参考值的差均小于等于容差。可从截图同时拾取坐标和参考色。 |
| 额外 OCR | 同一触发器中，连续读取不同框的 OCR 动作共享一张新截图。遇到点击、等待或重复读取同一个框时，下一段 OCR 会重新截图。 |
| 条件随机点击 | 在同一张新截图上检查各候选点的条件，从全部通过的不同坐标中等概率选择一个左击。 |
| 等待 | 暂停周期识别和触发操作，结束后继续本轮余下动作。等待或识别耗时造成的漏轮会跳过。「停止」可以中断等待。 |

每轮先截取一张画面并识别周期区域。触发条件共享当前画面的 OCR 结果。点击和等待之后，需要检查条件时会重新截图。

## 配置和结果

浏览器会保留编辑草稿。可把当前配置导出为 YAML，编辑后再导入。框的 `x`、`y` 是中心坐标，点击点和取色点使用所选截图内的整数像素坐标，原点在左上角。应用窗口关闭并重新打开后，需要在来源菜单里重新选择。

下面是一个触发器条目，可放入导出配置的 `triggers` 列表。示例使用名为「对手技能」和「对手血量」的两个区域。

```yaml
- name: 确认识别
  conditions:
    - type: confidence
      region: 对手技能
      threshold: 0.85
    - type: text
      region: 对手技能
      match: contains
      text: 破冰
  actions:
    - type: ocr
      region: 对手血量
    - type: click
      candidates:
        - point: {x: 620, y: 742}
          conditions:
            - type: color
              point: {x: 620, y: 742}
              reference: '#35a563'
              tolerance: 15
    - type: wait
      seconds: 0.5
```

每轮结果与上一条已保存的记录比较，忽略「时间」和「轮次」，置信度和耗时也参与比较。开启「输出置信度」或「记录耗时」时，实际执行 OCR 的轮次都会保存。其余轮次只在记录内容发生变化时保存，画面和区域状态每轮更新。使用「下载记录」获取当前任务保存在 `screen_recorder/recordings/` 的轮次。文件中的每个 YAML 文档以 `---` 开始，单行识别直接输出文字，多行用列表，空结果用 `null`。

YAML 下方显示各区域的最近有效文字和此后的帧差跳过次数。「本轮画面」用浅青色标出开启检测的周期区域，以及本轮执行了额外 OCR 的区域。轮廓沿用最近有效结果的位置，关闭检测的额外 OCR 使用整个选区作为轮廓。

勾选「记录耗时」后，`OCR耗时(ms)` 每次实际 OCR 记一行，含旋转裁剪、缩放和识别。合批时，左侧列出该批的备注名，右侧按相同顺序列出分摊后的耗时。同一帧复用结果时只保留首次用时，同一区域在新帧上再次识别会增加一行。计时默认关闭。

勾选「记录帧差值」后，每次重新执行 OCR 都会保存该轮，并在 `OCR帧差` 中按区域记录 0 到 1 的帧差。区域首次识别尚无比较基准，记为 `null`。同一区域一轮内多次识别时，按执行顺序追加数值。复用缓存时沿用原识别结果。

```yaml
---
轮次: 1
时间: '2026-11-27T11:30:00.123+08:00'
识别:
  对手技能: 破冰
触发器:
- 名称: 确认识别
  操作:
  - 额外识别:
      对手血量: 125/305
  - 点击: [620, 742]
  - 等待: 0.5
OCR耗时(ms):
- {'[对手技能, 回合数]': [31.672, 30.851]}
- {对手血量: [18.254]}
```
