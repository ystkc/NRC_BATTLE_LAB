# T12 规则与界面范围疑问

## T12-Q01　未出场保密是否涵盖房间准备和确认首发阶段

- 依据：`data/对战过程中的信息遮蔽规则.md:5` 说还未上场时对方无法看见任何信息。当前未明确区分准备阶段与已初始化战斗阶段。
- 当前行为：`nrc_platform/rooms.py:opponent_roster` 在尚未初始化时显式返回对方全部精灵名称/基础公开预览；`nrc_server/static/app.js:351-379` 的准备轮询取这些条目显示队伍。开局后则由观测投影替换未知条目，Chrome 的战斗弹窗实测只显示已出场者。
- 具体待解释：准备房间是否允许先看双方完整阵容名称（例如选首发前队伍预览），还是所有未出场身份从准备阶段就应隐藏？不请求用户解释已明确的战斗中遮蔽。
- 影响对象：所有双人房间的阵容提交、确认首发与准备界面；T11 主责准备投影，T12 协同显示。
- 冲突：规则文本没有准备阶段例外，但当前实现有明确“准备阶段只公开阵容名称”的注释，不能把该注释当作规则豁免，也不能未经解释就断言队伍预览一定禁止。
- 确认后验证：双 context 一方先提交多只阵容，另一方确认前查询 opponent-roster 和网页准备列表；若禁止则逐字段验证没有未出场名字/图片/特性，若允许则明确最早公开时点并继续验证开局后的未知投影。

其余 coverage 中“规则存疑”多数是独立参数/分支尚无定向运行证据，含坏JSON恢复、剪贴板拒绝、形态循环、网络失败与终局 UI；不把这些全部当作需要用户澄清的游戏规则。
