# T11 需补充与尚待证实

## T11-Q01：准备阶段是否允许向对方公开完整阵容名称

依据：`data/对战过程中的信息遮蔽规则.md` 对未上场精灵要求完全隐藏，但标题限定对战过程。`rooms.opponent_roster` 在未初始化时主动返回对方已提交阵容名称、属性、特性及可学技能池。需要明确准备阶段有无公开队伍预览规则，以及公开哪些字段。影响所有房间准备流程；确认后分别在未提交、单方提交、双方未确认、双方确认后测试同一身份可见性。当前仅作为规则存疑，不把准备期行为直接列确认缺陷。

## T11-Q02：技能冷却与特定技能效果的完整遮蔽

现有1007路径、T07水环公开修正归属反例和状态投影已审。`state.creature_effects` 的白名单是否完整表达所有242特性状态，仍依赖T09各原语“内部标记/公开状态/技能专属”的分类。没有明确分类的字段不自动宣称通过。需要从每个特性原文指定状态身份，建立白名单/组合状态条目双向映射；确认后补所有负状态、全技能修正和技能专属修正的双视角输入。

## T11-Q03：快照导入同ID替换与房间恢复协议

`platform.import_battle` 按快照battle_id替换现有内存局；RoomService准备成员不在平台快照内，HTTP未公开导入入口。现有协议说明这是本地可信载荷，不能当公开上传漏洞。本轮已验证平台观测、历史和pending的所采样往返；需要确认产品是否要求跨进程恢复房间身份/确认状态，再设计房间快照契约。影响重启恢复而非当前浏览器刷新；确认后以新进程恢复双方身份、pending、history和cursor。
