# 前半部分规则裁决后的修复计划

本文件是审计完成后的修复计划，不改变原审计基线。范围覆盖当前已回答的 `QUE-001` 至 `QUE-033`；`QUE-034` 及之后的问题继续留在存疑清单，不纳入本轮实施。

当前工作区基线为用户提交裁决后的 `898748756ef23c4970235f07ff5e2eb33e47fc25`。本轮用户新增的《状态的永久性》和《蓄力》作为后续实现的规则依据。

## 已确定的实现口径

| 问题 | 处理口径 |
|---|---|
| QUE-001 | 四指标全平为平局；按行动结算顺序判断 MP 归零，技能结算后先处理状态伤害，再到回合末；同一结算阶段仍按实际行动顺序决定先后。 |
| QUE-002、004、006、010 | 暂不实现秋收草系环境、奉献均匀分布、复杂静态分支和自动采集；保留当前行为并标记为暂缓项。 |
| QUE-003、013 | 资质倍数为 6；默认三项资质值改为 48，其他默认资料沿用当前规则，除非后续裁决另行指定。 |
| QUE-005 | 1002/1007 的差异按不同精灵数值处理；保留为数据输入差异，不能据此判定引擎错误。 |
| QUE-007、009 | 追查爬虫漏掉的名称/关系和旧 `skills.xlsx` 的生成来源；不能用模糊匹配或删除记录掩盖。 |
| QUE-008、016 | 接受相邻编号推断进化关系；进化允许一对一或一对多，不允许多对一、多对多；萌化必须得到唯一合法结果。 |
| QUE-011 | 同名记录按覆盖规则处理，但覆盖时必须留下非阻塞的控制台警告和来源信息。 |
| QUE-012 | 每只精灵只允许一条血脉。 |
| QUE-014 | 构建时载入状态属于恢复，不触发“新施加”特性；仍须检查免疫并向前端返回可观察的拒绝/修正信息。实际施加路径在免疫、打断或击杀后不得触发成功事件。 |
| QUE-015、019 | `skill_pool`、进化阶段、性格修正由平台读入并传给核心；借用/读心读取双方全队技能池，复制只读取己方技能池；平台缓存，不让核心查库。 `known_to_observer` 留在平台边界。 |
| QUE-017 | 支持合法的常驻首领形态；增加明确的合法首领精灵 ID 清单，提交阵容时拒绝其他首领形态。 |
| QUE-018、020、024 | 层数始终为整数；先对衰减量向下取整，再加原有增长量，最终结果独立限制在 0–99；状态效果完成后再执行回合阶段的衰减/增长。 |
| QUE-021 | 普通增益、减益和普通状态默认换人清除；冻结换人保留、倒下时清除一次，倒下后被对手效果重新施加的冻结保留；场地标记按己方/敌方独立保存并跨换人和倒下保留；复活只恢复满 HP 和能量。 |
| QUE-022 | HP 和最大 HP 为整数；百分比 HP 统一向下取整；毒/烧伤按属性伤害并经过属性抗性；毒/烧伤使用最大 HP；冻结阈值按不超过阈值判定。 |
| QUE-023 | 合法性检查集中在平台；核心接收平台已经解析并验证的战斗配置，不把用户输入校验扩散到核心。 |
| QUE-025 | 每只精灵、技能槽、特性效果和组合状态必须深拷贝；允许阵容出现同一精灵多次，但实例互不共享可变状态。 |
| QUE-026 | 石餐导致的技能自灭属于非法动作；陨石使先行动者倒下时，后行动直接取消，不算成功执行。 |
| QUE-027 | 寄生由被寄生者承受伤害并治疗寄生源，默认换人清除。 |
| QUE-028、033 | 蓄力规则以新文档为准：无嫉妒时第二回合只能免费使用原技能或换人，换人消耗蓄力；有嫉妒时可选任意技能或换人，选择其他蓄力技能时立即释放并消耗蓄力；受控不清除蓄力，控制结束后按规则在第三回合释放。 |
| QUE-029、031 | 不做全量重新生成或大范围重写；逐技能以原文核对范围，针对生成项修生成脚本/源配置并在审计副本验证，不手改生成文件；手写覆盖保持有效。 |
| QUE-030 | 一击必杀威胁只计算对手当前可用技能的确定性伤害，纳入天气等确定因素，不纳入随机最坏情况、反制技能或减伤技能。 |
| QUE-032 | 共鸣阶段优先于换人；双方共鸣完成并处理入场效果后，才进入换人。 |

## 仍需确认的边界

这些问题不阻塞计划编排，但实施前需要按下列建议定稿：

1. `QUE-015` 的 `source` 建议定义为数据来源标记（`team_input`、`catalog`、`generated`、`derived`、`assumption`），只用于追溯，不参与战斗规则，也不向对手暴露。若 `source` 有其他含义，需要改名或删除。
- 人工裁决：保持现状
2. `QUE-024` 的“不同阶段配置”是指同一组合状态键在入场、用技能、受击等不同触发阶段拥有不同参数。建议按“效果定义 + 触发阶段”区分配置；若这些阶段必须共用同一层数，再改为共享状态键。
- 人工裁决：除非显式强调，否则任何状态，包括组合状态，都是独立的（是指一个组合状态独立于另一个，不是指组合状态内部的独立），其具有自身特有的效果和触发阶段，不同状态的层数不能合并。
3. `QUE-027` 尚未明确寄生源换人或倒下后的治疗归属。计划暂按“寄生源实例绑定；源实例离场后该寄生关系清除”实现，需用户确认是否允许后台寄生源继续治疗。
- 人工裁决：治疗归属是施法方的在场精灵，不绑定施法精灵。
4. `QUE-032` 已确定阶段先后，但双方共鸣互相影响时的同速顺序尚未明确。计划采用现有统一行动排序和固定种子随机，仅保证换人不会提前发生。
- 人工裁决：共鸣阶段是包含施展共鸣魔法及共鸣魔法自带的效果（不含愿力冲击技能的施展）
5. `QUE-011` 的“控制台提示”在 Web 服务中建议实现为非阻塞日志/审计事件；不让服务器等待终端输入。若必须人工确认后继续，需另行定义交互协议。
- 人工裁决：保持现状
6. `QUE-017` 还需要实际的合法常驻首领 ID 清单。未拿到清单前只能完成校验框架，不能声称名单校验已完成。
- 人工裁决：目前已确认只有圣草迪莫、圣火迪莫、圣水迪莫、圣光迪莫。

## 修复顺序

### 1. 数据和规则输入边界

涉及 `nrc_platform/catalog.py`、`builder.py`、`input.py`、平台 schema，以及 `wiki_crawler/**`。

- 将默认资质值从当前默认值改为 48，并保留当前三项资质选择逻辑。
- 增加单血脉、合法首领 ID、进化图唯一性和阵容输入的集中校验。
- 为构建状态增加“恢复/拒绝原因”结果，免疫状态不得静默写入；不触发施加类特性。
- 把技能池、进化阶段、性格修正和数据来源作为平台输入快照缓存，核心只接收已解析值。
- 追查 44 个名称、2564 条关系和 `skills.xlsx` 的真实生成路径；先补证据和报告，再决定是否改爬虫。

### 2. 数值、层数和状态生命周期

涉及 `nrc_core/catalog.py`、`models.py`、`compound_status.py`、`constant.py`、`battle.py`。

- 统一六维计算精度、6 倍资质公式、整数 HP、百分比向下取整和属性伤害路径。
- 集中实现层数的整数化、增长/衰减截断、0–99 上限和状态效果后的阶段顺序。
- 把换人清除、倒下清除、冻结保留、场地标记保留、复活恢复拆成独立生命周期操作。
- 为寄生保存来源实例，明确来源离场后的清理点。
- 清理复制路径中的共享可变对象。

### 3. 行动编排、MP 和终局

涉及 `nrc_core/runtime.py`、`actions.py`、`battle.py`、`core.py`、`rules_support.py`。

- 重排共鸣、入场效果、换人、应对、技能、状态伤害、回合末的阶段边界。
- 实现 MP 在规定结算点的立即终局和四指标全平判定。
- 将石餐自灭和陨石后的后行动取消纳入合法动作及结算结果。
- 实现蓄力/嫉妒/受控/换人的完整合法动作矩阵，并确保蓄力消耗时点唯一。

### 4. 效果执行和技能池

涉及 `effect_data.py`、`effect_models.py`、`effect_engine.py`、`engine/handlers_skill.py`、`handlers_ability.py`、`executor.py`。

- 将借用/读心/复制改为读取平台注入的全队或己方技能池快照。
- 统一免疫、打断、击杀后的成功事件触发条件。
- 逐项核对技能和特性的范围、目标、条件、时点与附加效果；只修改有规则证据的配置。
- 一击必杀威胁计算接入确定性天气修正，并排除随机反制分支。

### 5. 平台和页面可见性

涉及 `nrc_platform/state.py`、`platform.py`、`rooms.py`、`nrc_server/**`。

- 展示状态恢复时的免疫/拒绝原因和数据来源摘要，但不泄露对手隐藏信息。
- 阵容提交时执行首领、血脉、重复实例和技能池约束。
- 保证构建警告、非法动作、蓄力状态和终局事件在双方视角中按既定可见性呈现。

### 6. 验证和交付

先用独立规则推导结果，再运行实现。至少覆盖：

- 默认资质 48、六维精度、HP/毒烧伤/属性抗性和层数边界；
- 换人、倒下、冻结、标记、复活、寄生来源；
- 共鸣先于换人、蓄力四种分支、石餐自灭、陨石取消后行动；
- MP 立即终局、四指标全平、固定种子复现；
- 全队技能池读取、技能实例隔离、合法首领和单血脉校验；
- 现有 19 个 pytest 用例、1002/1007 人工对局重新确认；涉及页面时用独立 Chrome Playwright 双 context。

每个失败项继续写入原审计目录的任务报告，使用“确认缺陷、未实现、规则存疑、检查受阻、未上线”分类；不把暂缓项计为通过。

## 暂不纳入本轮实施

秋收草系环境、奉献均匀分布、复杂静态分支、自动网络采集、`QUE-034` 之后未回答的问题，以及没有明确规则依据的全量生成文件重写，均保持现状并在后续计划中单独处理。
