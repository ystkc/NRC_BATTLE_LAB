# nrc_core training interface 补充约定

本文件补充 docs/nrc_core_training_interface.md 中仍可能被旧文字误导的部分；实现与本文件冲突时，以当前核心代码和 data/ 规则追溯记录为准。

## 分层

- `nrc_core.core.simulate_turn` 只接收完整核心状态和双方已解析动作，模拟一个回合，并返回核心生成的战报与显示威力。它不负责隐藏信息、用户操作校验或多回合决策记录。
- `nrc_platform.BattlePlatform` 保存多回合状态、替补决策、决策序号和奖励，向双方分别生成隐藏对手私有信息的观察，并拒绝非法 action。
- `nrc_core.training` 当前保留为训练接口适配器，内部已通过单回合核心执行；新平台接入优先使用 `nrc_platform.create_platform`。
- 核心战报事件和显示威力由 `simulate_turn` 计算后交给平台；平台不重复实现伤害或属性公式。

## 当前已实现

- 选择类技能如果数据描述能解析出固定的两个选项，会暴露两个独立 action key：skill:slot=<slot>:choice=0 和 skill:slot=<slot>:choice=1。
- 随机奉献按均匀分布抽取；随机结果在同一决策调用内由注入的 RNG 决定，可通过 seed 复现。
- 普通死亡/冻结力竭会扣对应玩家 MP；MP 为 0 或全队倒下立即终局，核心不产生平局。
- “离场”由玩家选择替补；“脱离”由核心从己方存活队伍随机选择替补。
- 技能 use_count 表示本次选择的实际独立执行次数，不表示历史计数或单次效果层数。

## 仍需上层协商

- 选择类技能的目标枚举，以及两个选项如何绑定目标/效果，数据目前没有足够明确的统一字段，核心不猜测。
- 各技能的应对历史计数口径仍需逐技能确认。
- 多次实际执行的特殊能量规则（动态费用、能量不足时是否存在例外）仍需逐技能确认；当前默认每次独立执行都按普通技能扣能量。
