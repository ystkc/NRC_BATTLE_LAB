# 双人对战职责重构核对

原调用链：server → BattlePlatform → NRCTrainingBackend → BattleSimulator → simulate_turn。平台依赖 AI 协议；server 另存回合、阵容、动作与历史，并在查询时追加已见身份。

新调用链：server 认证 → RoomService → BattlePlatform → BattleRuntime → simulate_turn。协议归核心；目录由平台显式注入；准备确认归平台房间，运行状态只由核心持有。

| 原入口 | 新入口或处理 |
|---|---|
| nrc_core.training | nrc_core.runtime，旧模块删除 |
| nrc_ai.contracts | nrc_core.contracts |
| 全局 pokemon_db/skill_db | 每个平台实例的 CoreCatalog |
| engine._monolith | context/helpers/filters/handlers/registry/dispatch/executor |
| server session 与遮蔽 | 平台房间及观测投影 |
| partial、HP 校准、训练 CLI | 停用 |
| 平台 v1 快照 | v2，拒绝旧版本 |

## 单独保留的规则疑点

BattleRuntime._prepare_decision 的全队力竭分支，winner 条件表达式看起来与存活方相反；沿用旧逻辑，需另行依据规则核对。

旧合法动作检查原始费用，显示计算费用修正；按计划将两者收口到同一费用入口，使动作与显示一致。

## 验证范围

固定数据库顺序阵容、种子及三回合聚能对比迁移前后的决策、双方观测、合法动作与事件。集中验证覆盖回滚、并发、重试、过期决策、快照续战、私有字段、实际换人记录及只读预览。聚能基线不能证明所有技能完全等价；效果拆分额外核对注册表和处理器原始主体。

本次结果：平台与双客户端 HTTP 集中测试共 6 项通过（含多平台目录隔离），四包编译、前端模块语法及启动检查通过。核心静态检查无上层导入。真实浏览器验收未执行：浏览器状态读取被自动审批服务的模型不可用错误阻断（404），需环境恢复后补验。

分阶段提交尚未创建：工作区允许代码写入，但 `.git` 写入被沙箱拒绝；随后本地提交的提权审批也遇到相同模型不可用错误。变更保留在工作区，未绕过审批。
